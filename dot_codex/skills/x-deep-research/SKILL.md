# X Deep Research

X の一次データ収集と Web 調査を組み合わせ、競合・市場・業界・指定テーマの調査レポートを作る。X データが不要な Web だけの調査は、通常のリサーチ手段を使う。

## 対象プロジェクトの確認

- 先に現在のリポジトリの `AGENTS.md`、`CLAUDE.md`、`instructions/`、`context/` を確認する。
- X API 用の `scripts/x-api.sh`、またはプロジェクトが指定する同等のラッパーがあればそれを使う。Finn、muumoo など特定組織の設定・アカウント・出力先を推測しない。
- レポートの出力先はプロジェクト固有の指示を優先する。指定がなければ既存の `output/reports/` を使い、無ければユーザーに指定された場所または作業用の Markdown ファイルへ保存する。
- プロジェクト内に `x-research.config.md` 等の設定があれば読み、定例ウォッチ対象・クエリ・ノイズ除外知見を反映する。

## モード

- ライト: 計画した X クエリを 1 ラウンド実行し、温度感・主要言及を整理する。
- 深掘り: Round 1 の結果から鍵アカウント、反応の大きい投稿、新語、疑問点を抽出し、スレッド・引用・追加クエリを追跡する。収穫逓減、予算不足、最大 4 ラウンドのいずれかで止める。
- ユーザーが「競合調査」「市場調査」「徹底的に」「詳しく」などと依頼したら、深掘りモードを候補にする。

## X API の安全な実行

X API は読み取り専用でも従量課金になり得るため、実行前に必ず以下を提示して明示承認を得る。

1. クエリ、対象アカウント、取得予定件数、ライト／深掘りの別
2. 概算コスト（取得件数 × 単価。`user-tweets` はユーザー照会分も含める）
3. 深掘りの場合の予算上限と、予算内で追加ラウンドを自律実行すること

承認前に API を呼ばない。承認範囲を超える場合は停止して追加承認を求める。認証切れ・401/403/429 等は無断リトライせず、エラーと未実施範囲を報告する。

一般的な取得方針:

- 日本語検索は必要に応じて `lang:ja`、RT 除外は `-is:retweet` を付ける。
- 競合・業界の定点観測は、汎用キーワード検索だけでなく公式アカウントの user timeline も使う。
- 直近検索に期間制限がある場合はレポートに明記し、古い情報は Web の一次情報で補完する。
- 生 JSON はリポジトリにコミットせず、プロジェクトのスクラッチパッドへ保存する。

## Web 調査

利用可能な深掘り調査スキルがある場合は、X で発見した要点・疑問・アカウントを引数に渡して裏取り・補完する。無い場合は利用可能な Web 検索・ページ取得手段で調査する。一次情報を優先し、各重要主張に出典 URL を付ける。

## レポート形式

通常は次の構成で Markdown を作る。ユーザーやプロジェクト指定の形式があればそちらを優先する。

```markdown
# X Deep Research: <テーマ>（YYYY-MM-DD）

## サマリー

## X での言及・動向
- 注目投稿: 本文の短い引用、author、日時、反応指標、URL
- 深掘り時はスレッド・引用から反応の論調
- ノイズ除外の内訳

## Web 調査結果
- 出典 URL 付きの検証結果

## 示唆・ネクストアクション

## 社内メモ
- 実行クエリ、取得件数、コスト、終了理由
- 生データの保存場所
```

推測・推定・未検証情報は明示し、観測事実と結論を混同しない。外部共有用の成果物では、社内メモや機密情報を分離・削除する。
