# SNSの出口設計

Research専用。ジャンル・媒体は固定しない。見る人の目的、媒体の役割、報酬が確定する成果をつなぐ。
**開始前に、このスキル所在を基準に `references/checklist.md` と `assets/output-template.md` を全文読む。**
共通の調査・モデル・質問・ブラウザ・外部書込み承認の規律を維持する。

## 1．対象とモード

- 新規設計：目的、対象者、媒体・地域・ジャンル、発信資源、予算・人の時間。
- 見直し：既存導線、変えたい点、段階別の実測・費用・契約条件。
- 参考分析：採用した対象と取得済みのプロフィール・リンク・資料。公開された導線を観察し、見えない売上・契約・率は未確認とする。

依頼で分かるモード・既決事項は再質問しない。仕事の範囲が変わる不足は親がask_userで1問ずつ確認し、子は親へ返す。対象なしを全件調査に広げない。

## 2．手順

1. 「誰をどこで集め、どの段階を通って、何の成果で収益を得るか」を重要な問いにする。入力事実・既決事項・相手の主張・未確認を分ける。
2. 集客／継続接触・関係づくり／収益化を各媒体へ割り当てる。同じ媒体の兼任、単一媒体の直接導線も候補にする。
3. 目的に合う収益モデルと導線を比較する。候補ごとに対象者、成果地点・単価・確定条件、掲載・流入・広告表示条件、離脱、計測、費用・人の作業をそろえる。適合する選択肢だけを扱う。
4. 段階ごとの率と費用で採算の式を作る。未知値は記号か「未確認」。説明用の数値には「仮置き・予測ではない」と書く。利益・入金・見直し条件を分ける。
5. 計測の分母・期間・識別子・成果の照合・欠測と重複を決める。媒体内の反応、LPクリック、発生、承認、入金を区別する。
6. 推奨導線、最大の弱点、成立条件、小さな試行、変更・停止・再確認条件を返す。仮説段階を成功扱いにせず、未確認の契約条件を承認済みにしない。

## 3．出力・引き渡し

`assets/output-template.md` の順で、重要な問い、導線比較、採算と計測、判定、決定・残論点、引き渡し、出典を残す。ResearchのJSONロジックツリーに根拠を接続する。
本スキルの成果物は出口設計。プロフィール・世界観・投稿ネタ10件・代表案3件は②の成果物とし、ここでは作らない。

- ディレクションが必要なら `sns-account-direction` へ、対象者・媒体の役割・出口・訴求の許容範囲・未確認を渡す。
- AI実現性が採算を左右するなら `sns-ai-feasibility` へ、必要な形式・頻度・費用・人の時間を渡す。
- 既存の成果物があれば読んで差分だけを検討する。連携先が利用不能なら、その点検は未実施とし、単独の部分成果と次の条件を残す。

外部アカウント分析は特徴・限界・転用条件を返す。見えない内部数字を理由に不合格にしない。
スキルの起動は、SNS投稿・登録・購入・契約・Notion書込みの承認ではない。新規実装・本番操作は別工程。
