# 出口設計の確認軸

## 1．導線と案件の確認

| 観点 | 残すもの |
|---|---|
| 誰に何の行動を求めるか | 情報を見たい人と、購入・申込したい人の違い。提供価値との一致 |
| 媒体の役割 | 集客、継続接触、収益化。媒体を増やす必要と各遷移の理由 |
| 収益モデル | アフィリエイト、直接送客契約、自社商品・サービス、スポンサー、媒体内収益等のうち適合する候補 |
| 成果 | 登録・有効リード・課金等の定義、単価、承認・否認・取消、帰属期間、入金条件 |
| 利用条件 | 掲載場所だけでなく流入元、LP経由、リンク機能、対象アカウント、地域、素材・広告表示 |
| 継続運用 | 情報・素材の供給、作成・更新・返信・計測、人の担当と予算 |
| 計測 | 媒体→外部到達→申込→承認。取得方法・欠測・二重計上・期間 |

LPは説明や計測の役割で比較する。「SNS不可」の意味を確認せず、LPを挟めば可能とは判定しない。適用条件の根拠は案件規約・権限のある相手の書面回答。媒体仕様は対象アカウント・地域・確認日を限定する。

## 2．採算の組み方

段階の単位をそろえる。率の分母は直前の段階。動画再生をユニークな到達人数や購買意思と読み替えない。複数SNSの重複人数は未確認なら限界として残す。

```text
承認成果の仮説 = 入口の観測数 × 各段階の移行率 × 成果承認率
確定報酬の仮説 = 承認成果 × 承認単価
現金収支 = 確定報酬 - 実支出
工数込み損益 = 現金収支 - 実作業時間 × 評価時給
```

対象モデルに応じて式を変える。スポンサーの固定報酬を成果単価モデルへ無理に入れない。再生成・検品・訂正・問い合わせ・初期設定も費用へ含める。承認待ちを確定売上にせず、収支と入金の時間差を示す。
仮の率で必要成果数・単価の感度を見ることはできるが、市場実績・成功保証とは書かない。共通の再生数・売上合格点は設けず、本人の条件に合わせて判断日と見直し条件を決める。

## 3．判定と分析モード

自作導線は「条件不足／試行設計あり・効果未確認／定めた条件で効果を観測」のどれかと理由を返す。未確認の重要条件には保留と確認方法を添える。試行設計は公開許可と別。
参考事例は観察・出典、解釈、限界、転用条件を分ける。売上や工数が非公開でも、観察できる導線の分析を残せる。

例：SNS→LP→事業者のリンクが見えるのは事実。LPが成約を増やしたか、報酬額、SNS由来流入の契約許可はリンクだけでは確認できない。
