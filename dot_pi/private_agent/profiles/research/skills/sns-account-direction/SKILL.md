# SNSアカウントのディレクション

Research専用。見る人への継続価値を、世界観・表現・投稿方針へ落とす。出口設計やAI制作可否の判定とは分ける。
**開始前に `references/checklist.md` と `assets/output-template.md` を全文読む。** パスはこのスキル所在を基準に解決する。
共通の調査・モデル・質問・ブラウザ・承認規律を維持する。投稿制作・公開の操作は本スキルに含めない。

## 1．入力

新規設計／既存方針の見直し、主目的、対象・利用場面、媒体・地域・ジャンル、発信資源、予算・人の時間、変更不可の条件を整理する。
①の出口設計や③の制約表が既にあれば読み、確定と仮を区別して引き継ぐ。出口未定・非販売目的でも設計できる。
仕事が変わる不足は親がask_userで1問ずつ確認し、子は親へ返す。複数案の時間・予算が共有か個別かを勝手に確定しない。質問できない評価ケースでは両解釈と限界を明記する。

## 2．設計

1. 「誰にどんな継続価値を、どんな世界観・表現で届けるか」を重要な問いにする。相手の関心と発信者の成果目標を分ける。
2. コンセプトの一文、世界観、発信者／キャラの立ち位置、語り口、視覚方針、投稿の柱、形式・頻度、扱わない内容、媒体の役割を具体化する。未選択の地域・業種を確定事項にせず、例に使うなら仮例と書く。
3. 視覚・文章の方針には実際の例を付ける。「親しみやすく」だけでなく、色・見出し・図解・情報量・語尾・誘導の見せ方まで決める。頻度は発信資源と③の未確認条件に合わせて仮置きする。
4. プロフィール案と投稿への具体化を作る。件数と目的は既存基準を参照し、提供価値・プロフィールの期待と照合する。
5. **既存点検：`../sns-account-concept/SKILL.md` と `../sns-account-concept/references/checklist.md` を全文読む。** 作成した案を「既存案の見直し」モードで点検する。承認済み項目名・判定を変えず、根拠・仮説・不足時の確認を残す。基準自体はここに複製しない。
6. 点検の不足を設計へ戻し、具体案、点検結果、未確認・修正理由、検証条件、③への制作要件を返す。

## 3．点検ができない場合

既存基準・参照資料が欠落または読込不能なら、設計の部分成果と「点検未実施」を分ける。10項目や合格を記憶から補完せず、必要なパス・再開方法を返す。全体を確認済み・完了とはしない。
参考アカウントの概念分析だけの依頼は既存 `sns-account-concept` の分析モードへ渡す。自作用の10ネタ・3案を参考分析へ強制しない。

## 4．引き渡し

`assets/output-template.md` の順に、決定事項・設計・具体案・点検・検証・引き渡し・出典を残し、ResearchのJSONロジックツリーへつなぐ。
①へは読者と商品・送客先の期待差、媒体の役割変更、制作負担を返す。
③ `sns-ai-feasibility` へは必要な本文・図・人物・音声・動画の品質、素材供給、頻度、予算・人の時間、検品条件を渡す。未実施の連携を実行済みとしない。
実在の人物・専門家へのなりすまし、架空の実績・体験・資格・読者の声を設計根拠にしない。キャラクターの設定と事実を分ける。
外部保存・契約・購入・公開の許可は別。技術的に生成できることを読者価値や事業成果の証明にはしない。
