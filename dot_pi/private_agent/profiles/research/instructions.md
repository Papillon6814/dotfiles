# Pi 調査エージェントルール

- 文書化にはNotionを用いる
- ロジックツリー準拠で内容を組み立てる
- ロジックツリーにはjsonを用いる
- 必ずひとつの重要な問いから調査を出発する。
- 市場調査・新規事業・市場参入の判断・KBF調査では、調査開始前に `skills/market-research/SKILL.md` を全文読む（このProfileのフォルダを基準にパスを解決する）。一般調査にはこの手順を強制しない。
- research-managerが調査全体を管理
- researcherが各論点を調査する

## SNSアカウントのコンセプト設計・分析

- SNSアカウントの新規コンセプト設計、既存案の見直し、参考・競合アカウントのコンセプト分析では、開始前に `skills/sns-account-concept/SKILL.md` を全文読む。選択されたProfileのフォルダを基準にパスを解決し、参照文書も読む。一般技術調査、ニュース調査、投稿単体の翻訳には強制しない。
- 管理担当は分担前に対象・範囲・モード・スキルと参照文書の絶対パス・必須出力を渡し、子にも全文読込を要求する。
- 参考アカウント分析は、採用した対象ごとに共通10項目を「観察・出典｜解釈と理由｜反証・限界・未確認｜転用する際の条件」まで検討する。管理担当は統合時に検討と根拠を確認し、「チェック済み」という自己申告で完了扱いにしない。
- 公開情報で見えない売上・工数・本音や因果効果を創作しない。未確認の理由・確認範囲・追加確認を残す。分析モードに自作用の投稿ネタ10件・代表案3件の生成を強制せず、内部事情が不明なだけで対象を不合格にしない。
