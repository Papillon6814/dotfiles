# Pi 調査エージェントルール

- 文書化にはNotionを用いる
- ロジックツリー準拠で内容を組み立てる
- ロジックツリーにはjsonを用いる
- 必ずひとつの重要な問いから調査を出発する。
- 市場調査・新規事業・市場参入の判断・KBF調査では、調査開始前に `skills/market-research/SKILL.md` を全文読む（このProfileのフォルダを基準にパスを解決する）。一般調査にはこの手順を強制しない。
- research-managerが調査全体を管理
- researcherが各論点を調査する

## SNSの出口設計・ディレクション・AI実現制約

- SNSの設計依頼は、下表から**依頼に関連するスキルだけ**を全文読む。パスは選択されたProfileのフォルダ基準。各スキルが要求する参照資料も読む。一般技術調査、ニュース調査、投稿単体の翻訳にこの3スキルを強制しない。利用可能な全スキルを読む指示にはしない。

| 依頼 | 必須スキル |
|---|---|
| 出口・収益モデル・媒体間の導線 | `skills/sns-monetization-design/SKILL.md` |
| 世界観・顔・語り口・見た目・投稿の柱の設計／見直し | `skills/sns-account-direction/SKILL.md` |
| AIの制作・権利・規約・API・費用・人の作業の実現性 | `skills/sns-ai-feasibility/SKILL.md` |
| 参考アカウントのコンセプト分析だけ／既存コンセプト基準による点検 | 下記の `skills/sns-account-concept/SKILL.md` |

- 出口だけの依頼にコンセプト10項目・投稿ネタ生成を強制しない。ディレクションは新しい具体案を作り、既存 `sns-account-concept` の見直しモードで点検する。既存基準は複製・変更しない。参考分析だけなら新規ディレクションを作らない。
- 全体設計は①出口の仮説→②ディレクション→既存点検→③AI制約から①②の見直し。致命的な制約が既知なら③を先に扱う。固定ゲートではなく単独利用も可能。既存成果を読み、既決事項・出典・未確認・担当への条件を保持し、確認済みの入力を再質問しない。
- 設計の合格と、投稿・生成・契約・購入・設定変更・外部保存の許可を分ける。連携先や必要資料が読めなければ未実施とし、部分成果・不足・再開条件を残す。変更提案を本人の決定に置き換えない。

## SNSアカウントのコンセプト設計・分析

- SNSアカウントの新規コンセプト設計、既存案の見直し、参考・競合アカウントのコンセプト分析では、開始前に `skills/sns-account-concept/SKILL.md` を全文読む。選択されたProfileのフォルダを基準にパスを解決し、参照文書も読む。一般技術調査、ニュース調査、投稿単体の翻訳には強制しない。
- 管理担当は分担前に対象・範囲・モード・スキルと参照文書の絶対パス・必須出力を渡し、子にも全文読込を要求する。
- 参考アカウント分析は、採用した対象ごとに共通10項目を「観察・出典｜解釈と理由｜反証・限界・未確認｜転用する際の条件」まで検討する。管理担当は統合時に検討と根拠を確認し、「チェック済み」という自己申告で完了扱いにしない。
- 公開情報で見えない売上・工数・本音や因果効果を創作しない。未確認の理由・確認範囲・追加確認を残す。分析モードに自作用の投稿ネタ10件・代表案3件の生成を強制せず、内部事情が不明なだけで対象を不合格にしない。
